PAY.JP does not provide pre-application screening. This checklist now separates the PAY.JP production-use application route from optional/fallback support inquiries. It does not authorize an account, application, inquiry, or implementation.

## PAY.JP production-use application — before future submission

- [ ] `PAYJP_PRODUCTION_APPLICATION_READINESS.md` reviewed
- [ ] Actual operator/application facts completed by Human
- [ ] Final intended service, Terms, Privacy, and Tokushoho URLs available
- [ ] Current PAY.JP application fields and requirements rechecked
- [ ] Security-declaration answers are truthful and supportable
- [ ] No unimplemented control or unpublished page is claimed as complete
- [ ] Sensitive evidence has an approved non-public storage location
- [ ] Human explicitly approved the exact application submission

## PAY.JP production-use application — after future submission

- [ ] Date/time and application/reference identifier recorded
- [ ] Exact application facts, service description, URLs, methods, and document references preserved
- [ ] Additional-information requests and exact responses preserved
- [ ] Status changes, PAY.JP/card-company outcomes, and all conditions preserved
- [ ] No approval or selection inferred before authoritative review evidence exists

No item in these PAY.JP sections is completed by this documentation task. Application status remains `Not submitted`.

## Optional support clarification or contingency-provider inquiry — before sending

- [ ] Provider name and correct contact channel verified
- [ ] Current official prohibited/restricted business page reviewed
- [ ] Inquiry draft matches current service design
- [ ] Service category is not disguised
- [ ] Price and commercial model are accurate
- [ ] Safety controls are described accurately
- [ ] No unimplemented feature is claimed as implemented
- [ ] No legal page is claimed as published if not published
- [ ] Operator contact information is real
- [ ] Human explicitly approved sending

For PAY.JP, this route may be used only for a specific clarification. It is not pre-application approval and does not replace production-application/review evidence.

## Optional/fallback inquiry — after sending

- [ ] Date recorded
- [ ] Channel recorded
- [ ] Exact sent text preserved
- [ ] Ticket/reference number recorded
- [ ] Response saved
- [ ] Conditions extracted
- [ ] Follow-up questions recorded
- [ ] Provider comparison updated
- [ ] No provider marked approved unless the response is authoritative approval under that provider's verified process

## Record location

- Inquiry status and response metadata: `PROVIDER_INQUIRY_EVIDENCE_LOG.md`
- Provider facts and comparison: `PROVIDER_COMPARISON.md`
- Evidence-based scoring: `PROVIDER_DECISION_SCORECARD.md`
- Selection prerequisites: `PAYMENT_PROVIDER_DECISION_GATE.md`

Unchecked items must not be inferred as complete. Verbal guidance, marketing copy, a blank application form, or an optional support clarification alone is not authoritative category/application acceptance.
