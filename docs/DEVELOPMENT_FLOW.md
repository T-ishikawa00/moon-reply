# DEVELOPMENT_FLOW.md

## 0. このドキュメントの目的

このドキュメントは、AIを活用した恋愛メッセージ分析・判断支援デジタルレポート「月の返事」を、検証MVPから最終理想形までどの順番で開発していくかを定義する。ユーザー向けには「恋のメッセージ鑑定ノート」と表現する。

現時点では本実装を行わない。
まずは検証に必要な資産を作り、Go条件を満たした場合のみWeb MVP実装に進む。

最重要方針：

- 需要検証なしにコードを書かない
- Phase 0は7日で強制終了
- 自己採点だけで進めない
- Day5から集客を始める
- 単発¥980が売れるまでサブスクを本命にしない
- Webで検証する。ネイティブアプリは後
- コイン/ポイント制は採用しない
- 危険相談は通常鑑定にしない
- AI利用は隠さない

## 7. Phase 2のAIパイプライン

AIは1回で全部やらない。

### Step 1：安全判定

危険フラグを判定する。

- 自傷
- 他害
- DV
- ストーカー
- 監視
- 未成年
- 脅迫
- 個人情報晒し

危険なら通常鑑定に進ませない。

### Step 2：構造化

自由入力を内部データに変換する。

例：

```json
{
  "relationship_type": "曖昧な関係",
  "last_contact": "3日前",
  "user_emotion": ["不安", "焦り"],
  "message_to_send": "忙しいかな？また落ち着いたら話したい",
  "followup_count": 1,
  "risk_level": "medium",
  "main_question": "送っていいか"
}
````

### Step 3：判定エンジン

低temperatureで4判定を出す。

* 送っていい
* 軽く送るならあり
* 今夜は待つ
* 今日は送らない方がいい

ここは安定性重視。

### Step 4：鑑定書生成

判定結果をもとに、鑑定書を生成する。

ここで月・夜・手紙のブランド世界観と言葉の余韻を入れる。月相その他の天体情報を分析根拠または未来予測に使用しない。

### Step 5：出力チェック

禁止表現が入っていないか確認する。

* 断定
* 不安煽り
* 回避訴求
* 依存誘導
* 医療/診断表現
* 相手操作表現

危険なら再生成または管理者確認。

## 10. Phase 5：ネイティブアプリ化

### 目的

Webで継続需要が見えた後に、スマホ体験を強化する。

ネイティブアプリ化の理由：

* 夜にすぐ開ける
* 保存ノートとして使いやすい
* 通知が使える
* App Store検索流入を狙える
* サブスクと相性が良い

### 作る条件

* Webで単発課金が成立
* 月額¥980〜1,500で継続率が見える
* 相手別ノートが使われる
* 3日後フォローが使われる
* 保存率が高い
* 法務/決済/プライバシーが固まっている

### 技術候補

* Expo React Native

理由：

* 既にExpoでアプリ提出経験がある
* iOS/Androidを同時に狙える
* Webで作った設計を移植しやすい
* IAP実装経験を活かせる

### App Store課金

iOSでは、月額サブスクは基本的にApple IAP。

* Auto-renewable Subscription
* Light plan
* Standard plan
* Premium plan

単発鑑定をアプリ内で売る場合も、Apple IAPの消耗型課金を検討する。

## 14. 最終理想形

最終的な月の返事は、恋愛不安に特化した恋愛メッセージ分析・判断支援サービスである。

相手別に利用者の入力履歴を記憶するAI鑑定ノート。

ユーザーにとっては、

* 返事待ちの夜に開く
* 送る前に言葉を整える
* 過去の恋の流れを見返す
* 同じ相手との変化を見る
* 3日後に振り返る
* 不安で暴走する前に止まれる

場所になる。

プロダクトとしては、

単発課金で入口を作り、相手別ノートで継続価値を作り、ネイティブアプリとサブスクで収益を安定させる。
