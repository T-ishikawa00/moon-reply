# M2-P1 Decision Policy

## Status

- Version: `decision-policy-v1.0.0`
- State: draft foundation; Human / ChatGPT review pending
- Owner: 月の返事 application policy
- Runtime implementation: not authorized

The model never defines the allowed decision set and has no override field.

## Eligibility boundary

Decision policy runs only when:

- eligibility is `ready`; and
- aggregate Safety is `normal_allowed`.

For `needs_more_information` or `safety_blocked`, `primary_decision` is null, the draft is not allowed, payment is false, and report generation is prohibited.

## Fixed decisions

| Priority | Code | Fixed label | Required draft behavior |

| 1 | `pause_additional_contact` | `こちらからの追加連絡を一度止める` | `not_allowed` |

| 4 | `wait_and_reassess` | `今夜は送らず、明日以降に再判断する` | `later_only` |

The table priority applies after Safety and information sufficiency. It operationalizes the Human-approved decision order; it is not a model ranking.

## Policy order

### 1. Safety

Any aggregate `needs_review` or `rejected` result stops normal policy. Do not calculate a romance decision, draft, report, or payment path.

### 2. Information sufficiency

When a material gap can change the allowed decision, return `needs_more_information`. Do not disguise missing information as `wait_and_reassess`.

### 3. Explicit boundary and repeated unanswered contact

Allow only `pause_additional_contact` when an applicable condition is confirmed:

- explicit no-contact request;
- temporary distance request;
- block or contact restriction;
- repeated unanswered contact;
- repeated apology or explanation;
- prolonged nonresponse after follow-ups;
- relationship closed with a boundary;
- repeated multichannel contact;
- third-party circumvention; or
- the other person explicitly controls restart.

Pause has no message draft. Resume policy is either `explicit_permission_required` or `other_initiated_only`.

### 4. Unanswered meaningful message from the other person

Allow `reply_now` when the other person sent a meaningful direct message or question that reasonably calls for a response and the user has not yet answered. An SNS reaction alone does not qualify.

### 5. Clear, low-pressure reason to initiate

Allow `send_now` when there is no unanswered user message or boundary and a concrete reason exists, such as:

- necessary schedule coordination;
- a material factual correction;
- promised required information;
- a practical return or logistics matter;
- a simple thank-you after a completed interaction; or
- one clear invitation that does not pressure for reassurance.

### 6. Wait and reassess

Allow `wait_and_reassess` when no earlier rule requires pause, reply, or send and additional contact tonight is not supported by a new material fact.

## Follow-up exceptions

Only application code may set:

- `none`
- `material_factual_correction`
- `same_day_schedule_change`
- `next_day_schedule_change`
- `promised_required_information`
- `safety_necessary_contact`

An exception is not permission to bypass an explicit no-contact boundary. `safety_necessary_contact` refers to safety-necessary, lawful contact selected by application policy or a Safety template; it is not a romance-message exception generated by the model.

## Allowed-set construction

The application produces:

- one or more allowed decisions;
- every disallowed decision with an allowlisted reason code;
- follow-up exception;
- draft policy;
- later-draft mode;
- pause reason; and
- resume policy.

The model receives this result and must:

1. select one allowed decision;
2. select the only decision when the set size is one;
3. cite observed fact IDs; and
4. preserve all policy-owned fields.

## Decision invariants

- A reply answers an incoming meaningful message; it is not a new chase.
- A send has one concrete purpose and leaves room not to answer immediately.
- Wait never contains a send-tonight instruction.
- Pause never contains a contact draft, workaround, or third-party contact plan.
- Every plan has exactly three day entries.
- Every ready plan includes at least one reassessment condition.
- Facts remain facts; interpretations remain possibilities.
- No decision asserts the other person's feelings, future reply, reconciliation, or probability.

## Counterfactual review

Cases sharing a counterfactual group must differ only through their supplied facts, not through policy drift. Review checks whether the changed fact moves the allowed decision in the expected direction. A model miss does not justify changing the oracle.

## Change control

A change to decision meaning, priority, allowed-set semantics, draft policy, pause/resume behavior, or acceptance gate is a major version change and requires Human review. Runtime use requires separate authorization after this draft is accepted.
