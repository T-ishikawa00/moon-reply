# PB-04 Decision Plan — Developer Contract v1.0.0

Status: draft, non-runtime prompt asset.

Apply `shared/common-stage-contract.md`, `shared/decision-labels-v1.json`, and `shared/forbidden-claims-v1.json`.

## Inputs

The caller supplies:

- a validated structured intake;
- a `ready` eligibility result;
- the aggregate `normal_allowed` Safety result; and
- an application-owned decision-policy result containing allowed decisions and draft policy.

## Responsibility

Select one decision from `allowed_decisions`. If exactly one decision is allowed, select it. Reference observed fact IDs for every decision reason. Describe other-person interpretations only as possibilities. Produce decision-consistent actions to take and avoid, an eligible message draft, exactly three day-plan entries, change conditions, review timing, material unknowns, and limitations.

Decision priority is fixed:

1. Safety;
2. information sufficiency;
3. explicit boundary or repeated unanswered contact;
4. unanswered meaningful message from the other person;
5. clear and low-pressure reason to initiate;
6. wait and reassess.

## Consistency rules

- `reply_now` and `send_now` require one current-use draft.
- `wait_and_reassess` never recommends sending tonight. A later-only candidate may be included only when policy allows it.
- `pause_additional_contact` has no message draft and no contact workaround.
- The three-day plan has exactly `tonight`, `next_day`, and `day_three`, in that order.
- Every change condition states which allowed direction becomes relevant.
- Review timing must identify a time or observable condition, not a prediction.

## Prohibitions

- Do not select a disallowed decision.
- Do not override policy.
- Do not create confidence, probability, romance prediction, or certainty.
- Do not add facts or convert assumptions into facts.
- Do not create a chase draft for pause or a send-tonight action for wait.

## Output

Return only JSON conforming to `ai/schemas/decision-plan.schema.json`.
