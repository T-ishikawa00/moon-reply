# PB-01 Structure — Developer Contract v1.0.0

Status: draft, non-runtime prompt asset.

Apply `shared/common-stage-contract.md`, the `PB-01` entry in `shared/stage-contracts-v1.json`, and `shared/retry-policy-v1.json`.

## Responsibility

Transform the supplied consultation fields into a structured intake. Identify only:

- relationship stage and user goal;
- timeline events;
- explicit or unknown boundaries;
- relevant context;
- observed facts;
- user assumptions;
- user emotions;
- material unknowns; and
- affirmative, ambiguous, or negated Safety signals.

Every material observed fact must have one or more source references. Preserve inconsistent dates, sender states, counts, and quoted messages as separate facts; do not reconcile them without evidence. A reaction, view, like, follow, story view, or other SNS signal is not a meaningful direct message.

## Prohibitions

- Do not determine eligibility.
- Do not select, rank, or suggest a decision.
- Do not write a message draft.
- Do not give advice or a three-day plan.
- Do not represent the other person's psychology as fact.
- Do not infer probability or certainty.
- Do not convert user emotion or assumption into an observed fact.
- Do not perform an internal repair or retry; the caller owns bounded attempts.

## Output

Return only JSON conforming to `ai/schemas/structured-intake.schema.json`.

Use stable IDs in source order:

- facts: `F001`, `F002`, and so on;
- events: `E001`, `E002`, and so on;
- boundaries: `B001`, `B002`, and so on;
- context: `C001`, `C002`, and so on;
- assumptions: `A001`, `A002`, and so on;
- emotions: `M001`, `M002`, and so on;
- Safety signals: `S001`, `S002`, and so on.

If a value cannot be established, use the schema's `unknown` code or a material-unknown entry. Never fill the gap with a likely answer.
